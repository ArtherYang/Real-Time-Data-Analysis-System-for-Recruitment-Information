## 1 简介

### 1.1 目的

本文档旨在定义**招聘信息实时数据分析系统**的完整软件需求，作为后续设计、开发、测试和验收的基准。文档面向以下读者群体：

- **开发团队**：明确功能边界与实现细节
- **测试团队**：构建测试用例的依据
- **课程评审老师**：评估需求分析完整性与合理性
- **项目管理者**：跟踪需求实现进度

### 1.2 范围

#### 1.2.1 产品名称
**招聘信息实时数据分析系统（Recruitment Data Analysis System, RDAS）**

#### 1.2.2 产品定位

本系统定位于**面向求职者与企业HR的招聘市场数据洞察平台**，核心价值主张为：

> "让求职者看清市场全貌，让企业招聘有据可依"

系统通过实时采集多平台招聘数据，经清洗、挖掘、可视化后，为两类核心用户提供决策支持。

#### 1.2.3 产品功能概述

| 功能大类 | 核心能力 |
|---------|---------|
| 数据采集 | 多平台爬虫/API接入、定时调度、增量更新 |
| 数据处理 | 数据清洗去重、字段标准化、NLP关键词提取 |
| 数据存储 | 结构化存储、索引优化、历史归档 |
| 数据分析 | 岗位热度、薪资趋势、技能需求、地域分布、经验学历分析 |
| 可视化展示 | 交互仪表盘、多维图表、数据导出、报告生成 |
| 用户管理 | 注册登录、角色权限、收藏订阅、浏览历史 |

## 2 总体概述

### 2.1 软件概述

#### 2.1.1 软件背景

截至2025年6月，中国在线招聘市场MAU达1.13亿，其中BOSS直聘（5400万）、智联招聘（2657万）、前程无忧（1765万）三家合计占据94.6%的用户使用时长。招聘平台每天产生海量岗位数据，但这些数据分散在不同平台，格式各异，求职者和企业HR难以系统性地获取和对比分析。

同时，AI技术正在重塑招聘行业。头部平台已接入大模型，从"人找信息"转向"AI匹配"。然而，市场上缺少一个**跨平台的、面向终端用户的招聘数据聚合分析工具**。

#### 2.1.2 竞品分析

| 竞品类别 | 代表产品 | 核心功能 | 与本系统的差异 |
|---------|---------|---------|--------------|
| 招聘平台内置分析 | BOSS直聘"有了"AI助手、智联招聘数据报告 | 平台内搜索推荐、行业薪酬报告 | 仅限单平台数据，不提供跨平台对比 |
| 专业HR SaaS | Moka、北森、飞书招聘 | ATS系统、招聘流程管理 | 面向企业付费，不对个人求职者开放 |
| 行业研究院 | 智联×北大研究、QuestMobile报告 | 宏观行业趋势分析 | 更新频率低（月/季度），缺乏实时性 |
| 数据服务商 | 灼识咨询、艾瑞咨询 | 市场规模测算、定制报告 | 高价定制，不对个人开放 |

**本系统差异化优势**：
1. **跨平台聚合**：同时覆盖至少3个主流招聘平台
2. **实时/准实时**：每日数据更新，而非月度/季度报告
3. **个人可及**：面向求职者免费开放基础功能
4. **多维分析**：薪资、技能、地域、经验四维交叉分析

### 3.2 子功能模块

---

#### F001 数据采集模块

**模块描述**：负责从多个主流招聘平台采集岗位信息，支持爬虫抓取和API接入两种方式，通过定时任务调度实现数据增量更新。

##### F001.1 多平台爬虫引擎

- **描述**：针对BOSS直聘、智联招聘、前程无忧等平台，使用Scrapy+Selenium实现岗位数据自动抓取。
- **输入**：
  - 目标平台URL列表及页面解析规则配置（JSON格式，含CSS选择器/XPath）
  - 爬取关键词列表（如"Python开发"、"数据分析师"）
  - 反爬策略参数：请求间隔(默认3-8秒随机)、User-Agent轮换列表、IP代理池地址
- **处理**：
  1. 系统读取解析规则配置文件，加载目标URL模板
  2. 按关键词构造搜索URL，放入Scrapy请求队列
  3. Selenium模拟浏览器渲染动态页面（处理JS加载内容）
  4. 解析页面HTML，提取岗位名称、公司、薪资、地点、经验要求、学历要求、技能标签、发布时间等字段
  5. 触发反爬检测时自动切换IP代理和User-Agent
  6. 采集成功的数据写入原始数据库，失败URL记录到重试队列（最多重试3次）
- **输出**：
  - 结构化岗位数据记录存入MySQL原始数据表
  - 采集日志（成功数/失败数/异常URL列表）
  - 异常告警（连续失败超过阈值时）

##### F001.2 API数据接入

- **描述**：接入有公开API的招聘平台，通过HTTP请求获取结构化岗位数据。
- **输入**：
  - 平台API端点URL及认证凭证（API Key/Token）
  - 请求参数：搜索关键词、分页参数、时间范围
- **处理**：
  1. 构造HTTP请求（含认证头和查询参数）
  2. 发送请求并解析JSON/XML响应
  3. 验证响应状态码和数据完整性
  4. 将API返回数据映射为系统统一字段格式
  5. 处理分页逻辑，遍历全部结果页
- **输出**：
  - 标准化岗位数据记录
  - API调用日志（请求时间/响应状态/数据量）

##### F001.3 定时任务调度

- **描述**：使用Celery+Redis实现定时采集任务调度，支持每日自动采集和增量更新。
- **输入**：
  - 任务调度配置（Cron表达式，如"每日凌晨2:00全量采集，每4小时增量更新"）
  - 各平台优先级权重
- **处理**：
  1. Celery Beat定时器按Cron配置触发采集任务
  2. 检查当前是否有同类任务在执行（防重复）
  3. 按平台优先级分配Worker进程
  4. 记录任务执行状态（排队中/执行中/已完成/失败）
  5. 任务完成后更新Redis状态标记
- **输出**：
  - 任务执行日志
  - 数据增量统计（新增/更新/不变记录数）

##### F001.4 采集状态监控

- **描述**：提供采集任务的可视化监控界面，管理员可查看实时状态和手动干预。
- **输入**：
  - 采集任务实时状态数据（来自Celery监控API）
  - 管理员操作指令（启动/停止/重试）
- **处理**：
  1. 轮询Celery任务队列状态
  2. 计算采集成功率、数据量趋势
  3. 异常状态触发告警（邮件/站内通知）
  4. 响应管理员手动操作指令
- **输出**：
  - 监控仪表盘（任务列表、成功率、数据量曲线）
  - 异常告警通知

#### F002 数据处理模块

**模块描述**：对采集的原始数据进行清洗、标准化和NLP处理，确保数据质量满足分析要求。

##### F002.1 数据清洗与去重

- **描述**：去除无效数据、重复记录和异常值，保证分析数据的基础质量。
- **输入**：
  - 原始岗位数据记录（来自采集模块）
  - 清洗规则配置：必填字段列表、薪资范围合理性区间、去重匹配字段
- **处理**：
  1. 检查必填字段（岗位名称、公司名称）是否为空，空值记录标记为无效
  2. 验证薪资合理性：月薪范围1000-200000元，超出标记异常
  3. 基于（岗位名称+公司名称+发布时间）组合键去重
  4. 模糊匹配去重：使用文本相似度（difflib）识别同公司同岗位的重复发布
  5. 异常值标记为"待人工审核"
- **输出**：
  - 清洗后的有效数据记录
  - 数据质量报告（有效率、去重率、异常率）

##### F002.2 字段标准化

- **描述**：将不同平台的字段格式统一为系统标准格式，便于跨平台对比分析。
- **输入**：
  - 清洗后的岗位数据
  - 字段映射规则：各平台原始字段名→系统标准字段名
- **处理**：
  1. 岗位名称标准化：去除空格/特殊符号，统一大小写，按岗位分类体系归类
  2. 薪资标准化：统一转换为"月薪（千元）"格式，面议岗位标记为特殊值
  3. 经验要求标准化：映射为"应届生/1-3年/3-5年/5-10年/10年以上/不限"
  4. 学历要求标准化：映射为"不限/大专/本科/硕士/博士"
  5. 城市标准化：统一为地级市名称，去除区县级后缀
- **输出**：
  - 标准化后的岗位数据
  - 映射失败记录（无法标准化的异常值）

##### F002.3 NLP关键词提取

- **描述**：使用Jieba分词从岗位描述中提取技能关键词和技术栈标签。
- **输入**：
  - 岗位描述文本（JD）
  - 自定义技能词典（技术栈名称、软技能术语）
- **处理**：
  1. 加载自定义词典（Python/Java/React等500+技术术语）
  2. Jieba分词处理岗位描述文本
  3. 基于TF-IDF提取Top 10关键词
  4. 关键词归类：编程语言/框架/工具/软技能/行业知识
  5. 计算各技能的市场需求频次
- **输出**：
  - 岗位技能标签列表
  - 技能需求频次统计

##### F002.4 数据质量评估

- **描述**：定期评估数据库中的数据质量，生成质量评估报告。
- **输入**：
  - 处理后的数据记录
  - 质量评估指标定义：完整度、准确度、时效性
- **处理**：
  1. 计算各字段完整度（非空率）
  2. 抽样人工校验数据准确度（每1000条抽10条）
  3. 检查数据时效性（距发布时间的天数分布）
  4. 生成综合质量评分（0-100分）
- **输出**：
  - 数据质量评估报告
  - 低质量数据范围标记

#### F003 数据存储模块

**模块描述**：设计并实现系统数据库，支持高效的数据读写和索引查询，管理历史数据归档。

##### F003.1 数据库设计

- **描述**：设计MySQL数据库表结构，包括岗位表、用户表、分析结果缓存表等。
- **输入**：
  - 数据实体定义（岗位、用户、分析结果、采集日志等）
  - 实体关系需求
- **处理**：
  1. 设计ER模型，定义实体间关系
  2. 设计表结构（字段名、类型、长度、约束）
  3. 建立主键、外键和索引
  4. 编写DDL建表语句
  5. 初始化数据库
- **输出**：
  - 数据库ER图
  - DDL建表脚本
  - 数据库字典

##### F003.2 索引优化

- **描述**：针对高频查询场景建立合理索引，优化查询性能。
- **输入**：
  - 查询频率分析（高频查询字段统计）
  - 慢查询日志
- **处理**：
  1. 分析Top 10高频查询的WHERE/GROUP BY/ORDER BY字段
  2. 建立组合索引（如：岗位名称+城市、发布时间+薪资）
  3. 使用EXPLAIN分析查询计划
  4. 定期重建索引
- **输出**：
  - 索引设计方案
  - 查询性能对比（优化前后）

##### F003.3 历史数据归档

- **描述**：对超过30天的岗位数据执行归档，保证主库性能。
- **输入**：

  - 归档触发条件（定时/存储空间阈值）
- **处理**：
  1. 查询发布时间超过阈值的岗位记录
  2. 将记录迁移至归档表/归档库
  3. 验证归档数据完整性

  5. 更新归档日志
- **输出**：
  - 归档数据文件
  - 归档操作日志

#### F004 数据分析模块

**模块描述**：对清洗后的岗位数据进行多维度统计分析，为可视化展示提供数据支撑。

##### F004.1 岗位热度分析

- **描述**：统计各岗位类型的需求量及变化趋势，支持按时间维度对比。
- **输入**：
  - 标准化岗位数据
  - 用户查询参数：时间范围、岗位类型、城市
- **处理**：
  1. 按岗位分类聚合统计岗位发布数量
  2. 计算环比增长率（本周vs上周vs上月）
  3. 按发布时间绘制需求趋势曲线（每日/每周）
  4. 计算岗位热度指数（基于发布量、浏览量的加权算法）
  5. 生成Top 20热门岗位排行
- **输出**：
  - 岗位热度排行数据
  - 岗位需求趋势时间序列
  - 热度指数

##### F004.2 薪资趋势分析

- **描述**：统计各岗位类型在不同城市、不同经验段的薪资分布。
- **输入**：
  - 标准化岗位薪资数据
  - 用户筛选条件：岗位名称、城市、经验段
- **处理**：
  1. 按岗位分类统计薪资中位数、平均数、25分位、75分位
  2. 按城市/经验段分组计算薪资统计
  3. 计算薪资与经验的回归关系
  4. 排除"薪资面议"记录后计算有效薪资统计
- **输出**：
  - 薪资分布统计数据（中位数/均值/分位数）
  - 薪资-经验关系矩阵
  - 城市薪资对比数据

##### F004.3 技能需求分析

- **描述**：基于NLP提取的技能标签，统计市场最热门的技能需求。
- **输入**：
  - 岗位技能标签数据（来自F002.3）
  - 用户筛选条件：岗位分类
- **处理**：
  1. 统计各技能标签的出现频次
  2. 计算技能关联度（共同出现的技能对）
  3. 按岗位分类统计Top技能需求
  4. 计算技能薪资溢价（拥有某技能的平均薪资 vs 无该技能的平均薪资）
- **输出**：
  - 技能需求频次统计
  - 技能关联网络数据
  - 技能薪资溢价数据

##### F004.4 地域分布分析

- **描述**：统计岗位在全国各城市/地区的分布情况，支持城市间对比。
- **输入**：
  - 标准化岗位地域数据
  - 用户筛选条件：岗位类型、薪资范围
- **处理**：
  1. 按城市聚合岗位发布数量
  2. 计算各省份/城市群岗位集中度
  3. 计算城市-岗位类型交叉分布矩阵
  4. 计算岗位集中度指数（CR5：TOP5城市占比）
- **输出**：
  - 城市岗位分布数据
  - 城市群集中度统计
  - 岗位-城市交叉分布矩阵

##### F004.5 经验学历分析

- **描述**：统计岗位对工作经验和学历要求的分布情况。
- **输入**：
  - 标准化岗位数据（经验要求、学历要求字段）
  - 用户筛选条件：岗位类型
- **处理**：
  1. 按经验段统计岗位数量和占比
  2. 按学历要求统计岗位数量和占比
  3. 分析经验×学历交叉分布
  4. 计算各经验/学历段的平均薪资
  5. 分析"经验要求通胀"趋势（同一岗位类型经验要求随时间的变化）
- **输出**：
  - 经验要求分布数据
  - 学历要求分布数据
  - 经验×学历×薪资交叉分析数据

#### F006 用户管理模块

**模块描述**：提供用户注册登录、角色权限管理、收藏订阅等基础用户功能。

##### F006.1 用户注册登录

- **描述**：支持邮箱/手机号注册和登录，提供JWT令牌认证。
- **输入**：
  - 注册：邮箱/手机号、密码（8-20位，含字母和数字）、昵称
  - 登录：账号、密码
- **处理**：
  1. 注册时验证账号唯一性和密码强度
  2. 密码使用bcrypt哈希加密存储
  3. 登录时验证账号密码，生成JWT访问令牌（有效期24h）和刷新令牌（有效期7天）
  4. 支持"记住我"功能（延长令牌有效期至30天）
  5. 登录失败超过5次，锁定账号15分钟
- **输出**：
  - 注册成功/失败提示及原因
  - 登录成功返回JWT令牌
  - 登录失败提示及剩余尝试次数

##### F006.2 角色权限管理

- **描述**：支持管理员为用户分配角色（普通用户/企业HR/管理员），控制功能访问权限。
- **输入**：
  - 管理员操作指令：用户ID、目标角色
  - 权限配置表
- **处理**：
  1. 验证操作者是否为管理员角色
  2. 更新目标用户的角色字段
  3. 权限中间件按角色组加载权限规则
  4. 前端路由守卫根据角色控制页面访问
- **输出**：
  - 角色更新成功提示
  - 被修改用户下次请求时权限生效

##### F006.3 收藏与订阅

- **描述**：用户可收藏感兴趣的岗位类型，订阅特定条件的更新通知。
- **输入**：
  - 收藏：岗位ID或筛选条件组合
  - 订阅：筛选条件（岗位/城市/薪资范围）+ 通知频率
- **处理**：
  1. 将收藏/订阅条件存入用户偏好表
  2. 每日定时任务根据订阅条件匹配新数据
  3. 有更新时生成站内通知（消息中心小红点）
  4. 可选邮件通知（每日摘要/即时通知）
- **输出**：
  - 收藏/订阅成功确认
  - 更新通知消息

##### F006.4 浏览历史

- **描述**：自动记录用户的岗位搜索和浏览行为，支持回溯查看。
- **输入**：
  - 用户操作行为数据（搜索关键词、点击的岗位、查看的图表）
- **处理**：
  1. 前端埋点捕获用户行为，异步发送到后端
  2. 后端将行为数据写入Redis（最近50条），定时同步到MySQL
  3. 用户可查看/清空浏览历史
  4. 基于浏览历史推荐相关岗位分析
- **输出**：
  - 浏览历史列表（按时间倒序）
  - "基于你的浏览记录"推荐模块
