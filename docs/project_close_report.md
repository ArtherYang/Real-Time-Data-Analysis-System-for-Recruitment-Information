## 1 项目概述

### 1.1 项目背景

当前求职市场信息不对称问题突出——求职者难以全面了解目标岗位的薪资水平、技能要求和地域分布，企业 HR 也难以高效获取竞品招聘策略。本项目构建了一套**从数据采集到可视化展示的全链路数据平台**，面向求职者和企业 HR 提供招聘市场数据洞察。

### 1.2 核心能力

```
多平台招聘数据 ──→ 实时采集 ──→ 清洗标准化 ──→ 多维分析 ──→ 可视化大屏
                       │                │              │
                  反爬对抗 + 去重    分层存储 + 缓存   热度排名 + 薪资分布
                                                     区域分析 + 技能词云
```

| 模块 | 能力 | 量化指标 |
|------|------|---------|
| 🔍 数据采集 | 多平台爬虫，增量去重，反爬对抗 | 2 个平台（BOSS + 51job），UA 轮换 / IP 代理 / Cookie 持久化 |
| 🧹 数据处理 | 薪资解析、字段标准化、管道清洗 | 15+ 薪资格式解析，7 类字段标准化 |
| 🗄️ 数据存储 | MySQL + Redis 分层存储 | 6 张业务表，14 个复合索引 |
| 📊 分析引擎 | 热度排名、薪资分布、区域分析、技能词云 | 4 大分析模块，缓存加速 1h TTL |
| 📈 可视化 | Dashboard + 3 个专项分析页 | 9 种图表组件（折线/柱状/饼图/词云/热力） |
| 👤 用户系统 | JWT 双令牌认证 + 账户锁定 | bcrypt 加密，RBAC 三级角色 |
| 🚀 DevOps | 容器化 + CI/CD + 监控 + 日志 | 11 个 Docker 服务，Grafana 面板，Loki 日志 |

## 2 技术栈

### 2.1 全链路架构

```
┌──────────────────────────────────────────────────────────────────┐
│                         展示层                                    │
│     Vue 3 + Vite + Element Plus + ECharts + Pinia                │
│     Dashboard | SalaryAnalysis | CityAnalysis | SkillAnalysis     │
└────────────────────────────┬─────────────────────────────────────┘
                             │ HTTP REST (Nginx 反向代理)
┌────────────────────────────▼─────────────────────────────────────┐
│                       接口层 + 业务层                              │
│     Flask + Gunicorn + Celery Worker + Celery Beat               │
│     /api/v1/jobs | /analysis | /auth | /export                   │
└────────────────────────────┬─────────────────────────────────────┘
                             │ SQLAlchemy ORM + redis-py
┌────────────────────────────▼─────────────────────────────────────┐
│                         数据层                                    │
│     MySQL 8.0 (业务)  +  Redis 7 (缓存/MQ)  +  JSON (Mock)       │
└────────────────────────────┬─────────────────────────────────────┘
                             │ Docker Compose
┌────────────────────────────▼─────────────────────────────────────┐
│                      基础设施层                                    │
│     Nginx + Prometheus + Grafana + Loki + Promtail               │
│     GitHub Actions CI/CD (.github/workflows/)                     │
└──────────────────────────────────────────────────────────────────┘
```

### 2.2 技术选型一览

| 层次 | 技术 | 选型理由 |
|------|------|---------|
| 后端框架 | **Flask 3.x** | 轻量灵活，学习成本低，课程评审友好 |
| ORM | **SQLAlchemy 2.x** | Python 生态标准，模型定义 + 连接池 |
| 业务数据库 | **MySQL 8.0** | 招聘数据天然结构化，关系型最优 |
| 缓存 | **Redis 7.x** | 分析缓存 1h TTL，复用为 Celery 消息代理 |
| 爬虫 | **自研 (Requests + BS4)** | 平台差异大，自研更灵活可控 |
| 异步任务 | **Celery 5.x** | Worker 异步处理 + Beat 定时调度 |
| 前端框架 | **Vue 3 + Vite** | 中文文档好，Element Plus 组件丰富 |
| 可视化 | **ECharts 5.x** | 图表类型最全，中文文档，大屏适配 |
| 容器化 | **Docker + Compose** | 11 服务编排，一键启动，环境一致 |
| 反向代理 | **Nginx** | 前端静态文件 + API 代理，单入口 |
| WSGI | **Gunicorn** | 生产环境多 Worker，替代 Flask 内置服务器 |
| 监控 | **Prometheus + Grafana** | 指标采集 + 面板可视化，业界标准 |
| 日志 | **Loki + Promtail** | 轻量日志聚合，与 Grafana 统一面板 |
| CI/CD | **GitHub Actions** | 自动构建 + 测试 + 镜像推送 |

## 4 创新点

### 4.1 AI 协作开发范式（"人类指挥官 + AI 执行单元"）

| 维度 | 传统开发 | 本项目实践 |
|------|---------|----------|
| 编码方式 | 纯手写 | AI 生成初稿 → 人工审查修正 |
| 效率提升 | — | **75-85%** 编码时间节省 |
| 质量控制 | Code Review | "三查"机制（事实/逻辑/一致性）+ 决策日志 |
| 文档产出 | 后期补 | 与代码同步推进（10 份文档贯穿全程） |
| 过程记录 | 无 | AI 协作反思日志（每次记录 AI 产出 + 修正 + 效率评估） |

**核心原则**：AI 是执行单元，人是决策者——技术选型、架构设计、安全策略 100% 由人主导。

### 4.2 全链路数据闭环

不同于单一模块的课程项目，本系统覆盖了**数据工程的完整生命周期**：

```
采集 → 传输 → 清洗 → 存储 → 计算 → 展示 → 运维
  │      │      │      │      │      │      │
 爬虫  Celery  Pipeline MySQL 分析引擎 ECharts Docker+监控
```

每个环节都有对应的代码实现、测试覆盖和文档支撑，体现了系统工程的完整性。

### 4.3 DevOps 能力闭环

从代码提交到生产可观测，形成完整链路：

```
git push → GitHub Actions → 自动测试 → 构建镜像 → Docker Compose 部署
                                                          │
                                            ┌─────────────┼─────────────┐
                                            ▼             ▼             ▼
                                        Prometheus     Grafana     Loki+Promtail
                                        (指标采集)     (面板展示)    (日志聚合)
```

**11 个容器服务**、**7 条告警规则**、**2 个预配置 Grafana 面板**，使课程项目达到了接近生产级的运维标准。
